Native scratch flag row
-----------------------
The worker reads the flag at startup and creates a float32 row in native
scratch storage. Scratch slot 12 begins with:

  float[0..3] = four 16-bit words containing an eight-byte process key
  float[4]    = flag length
  float[5+i]  = key[i % 8] XOR flag[i] XOR 0xa5

The row is large enough to hold a complete 4 x 24 expert weight.

Extension handling
------------------
For an extension tensor (record flag bit 0 set), the native parser replaces
the normal data pointer with:

  scratch_base + author_slot * 16 * sizeof(float)

It validates:

  author_slot * 16 + logical_elements <= 0x120

Thus slot 12 with shape (4, 24), or 96 logical elements, is accepted because:

  12 * 16 + 96 = 288 = 0x120

Name hashing
------------
state = identity_salt XOR 0x9e3779b9
for each UTF-8 byte b:
    state = ROL32(((b XOR state) * 0x85ebca6b) mod 2^32, 13)

x = state XOR (name_length * 0xc2b2ae35)
x ^= x >> 16
x *= 0x7feb352d
x ^= x >> 15
x *= 0x846ca68b
x ^= x >> 16

The native lookup compares this 32-bit value only. It never confirms the full
tensor name. An extension record with a different name but the same salted
hash can therefore replace a graph-bound expert weight in the native view.
